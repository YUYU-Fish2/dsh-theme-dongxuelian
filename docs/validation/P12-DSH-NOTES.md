# P12-DSH 首稿说明：窗口模式连续纸面

2026-10-20。范围仅 `client.js` 的 `SCENE_CSS` 和本文。未改测试、版本、素材、JS 生命周期、Theme token、字号、宿主/插件/profile/模型/权限；未运行 shell、Git、测试、浏览器、网络或真实宿主。以下只是待 Codex 实窗核对的首稿，不是视觉验收结论。

## 实际修改

### 1. active 滚动容器所有尺寸透明、全列

基础规则（不再区分宽度）改为：

```css
[data-slot="main.conversation"] > div[data-phase="active"] [data-conversation-scroll] {
  width: auto;
  min-width: 0;
  margin-inline: 0;
  background: transparent;
}
```

- 删除了原来的 `margin-right: var(--dxl-scene-gutter)`。
- 删除了窄列 scroll 自己的 `#F7F3EB` + `paper.webp` 平铺。
- 纸纹仍只由 `[data-slot="main.conversation"] > div[data-phase]` 和侧栏盒绘制；场景仍只有根 `::before` 一张图，没有新增伪元素、第二场景或渐变桥。
- 代码块 `pre` 的 `#FFFDF8` 保留；消息、气泡、输入等宿主自己的实底未改。

### 2. 取消 reserved gutter，正文按实际列宽

基础 active 内容规则改为：

```css
--dsh-chat-content-width: min(var(--dsh-chat-user-width, 960px), calc(var(--dsh-conversation-column-width) - 48px));
--dsh-composer-card-max-width: calc(var(--dsh-chat-content-width) + 32px);
```

- 删除了 `--dxl-scene-gutter` 及 `900px`、`640px` 两处 gutter 覆盖。
- 正文不再为人物预留一条 220–340px（窄列 160–220px）的右侧空间，只扣左右各 24px 的正常边距。
- 960px 只作为正文上限，继续尊重宿主已有的 `--dsh-chat-user-width`。
- 输入卡仍比正文宽 32px；没有改输入框、菜单、焦点或发送按钮的规则。

### 3. 900px 起复用 P11 左阅读座/输入座

把原先只写在 `@container dxl-reading (min-width: 1100px)` 里的 active 几何移到新的 `@container dxl-reading (min-width: 900px)`，没有复制整段：

- `--dxl-stage-inset: max(0px, (列宽 - 1920px) / 2)`
- `--dxl-reading-seat: max(768px, min(列宽, 1920px) * .56)`
- `--dsh-chat-content-width: min(用户宽 960, 座宽 - 96px, 960px)`
- 官方 session 和 composer 座宽为阅读座，左偏移为 stage inset，右偏移 0；scroll 本身仍全列。
- 输入座宽 `min(正文 + 224px, 100%)`，输入卡上限 `正文 + 160px`。
- 左右宽度柄沿用 P11 的计算，围绕 768px 座宽下限；正文上限至少 672px，高于宿主 640px 拖动下限。
- 两张座加了 `max-width: 100%`，避免 900px 附近被原生滚动条占掉十几像素后产生整页横溢。

`>=1100px` 的 hero 输入规则、composer resting shadow 和原 3:2 场景几何保持原位，未改值。

### 4. 插画层按宽度柔化，不动文字

只对 active 根 `::before` 增加/覆盖 `mask-image`：

- `900–1099.98px`：基础 720px 场景改到 `right -120px`，水平方向从 54% 透明开始，经 7%/22% 黑，到 98% 才完全显示；仍保留上下 32px 渐隐。
- `<900px`：沿用 58% 高度、`right -110px`，水平方向 60% 前透明，76%/90% 为 3%/10% 黑，末端最多 24%；上下 64px 渐隐。1024 窗口或正文列不足 900px 时不再让大幅人物墨迹穿过正文。
- `<640px`：场景缩到 50% 高度、`right -84px`，68% 前透明，末端最多 20%；极窄文字优先。
- 没有给消息、正文、控件、气泡或滚动条设置 `opacity`、`mask` 或 `filter`。
- 没有隐藏滚动条、拖柄或菜单伪元素。

## 未测项与风险

- 未运行 `node --test`、`scripts/check.mjs`、ModuleLoader、`npm pack`、真实 DSH、Chrome 或任何窗口；不声明 18 项回归、纸面连续、无整页横溢、焦点/菜单/滚动或深浅启停通过。
- 未看 `1310×790`、`1625×968`、`1024`、`800`、`640` 以下实际像素；不能声称窗口已与全屏视觉一致。
- 900px 是硬阈值：899.98px 时正文约 852px，900px 时切到 672px，窗口跨过该宽度会有一次明显收窄。是否可接受、是否需要在 760–900 增加过渡，需实窗判断；本稿按任务单优先覆盖 >=900。
- `max-width: 100%` 和 `width: min(..., 100%)` 的百分比以滚动内容盒为基准，实际是否把滚动条宽度算进去、宿主是否使用 `border-box`，未实测；若 900px 仍有 1–15px 横溢，需要 Codex 按真实盒模型修正。
- 宽度柄仍按 P11 公式围绕阅读座中心；900px 时左柄约 14px、右柄约 744px。未验证真实拖动、640px 下限、首次拖动空程和两柄命中区域。
- 输入菜单未改，但它现在位于更窄的 composer 座上；菜单方向、溢出和被裁切未验证。
- `900–1099px` 的根图仍是基础 720px 高度场景，只改位置和 mask；人物是否被遮得过多、mask 边缘是否出现硬线，未看。
- `<900px` 插画被明显压到右侧低透明度，可能出现“人物只剩右缘残影”的观感；这是文字优先的取舍。`<640px` 更弱。是否过弱需实窗判断。
- 未确认 `[data-conversation-content]` 或其祖先是否还有主题之外的实底；若有，scroll 透明后仍可能挡住根纸纹/场景。
- 未确认 `@container` 在宿主真实 Chromium 中同时接受 `min-width` + `max-width` 和 `.98` 小数；按现有 P11 的 `@container` 实测基础推断可用，但本轮未跑。
- 未确认删除 scroll 纸纹后，根纸纹与阅读座、输入卡、代码块之间没有新的色差或接缝；未做像素采样。
- 未改 `>=1100px` 已有几何和场景；但基础 scroll 规则现在也作用于 >=1100，理论上只是与旧宽列规则重复且更早生效，仍需实窗确认无回归。
- 未验证侧栏展开/收起、深浅色切换、插件停用释放、其他插件共存；这些逻辑未动，但不能用“未改”代替回归。
